# 0046 — A bookkeeping miss never trips, and a trip holds only what it threatens

Date: 2026-10-21
Status: accepted. Ruled with Lachy in the 2026-10-21 grill that followed `chorus-rollout-2026-10-18`. Built by p29-2 (2026-10-27). Amends ADR 0030's git-env canary consequence and the Git-env hold.

## Context

A git-env trip holds the whole queue (nothing starts, integrates or merges) until Lachy acks it through `/thread:repair` § 3e. In `chorus-rollout-2026-10-18` both trips were false: the lead had skipped arming a window (p80-1 on 19 Oct, p82-2's seeded revise the same evening), so the check found an old record. Each time an agent showed the same evidence (the clone's default equal to `origin/<default>`, no local-only commit, a clean tree) and Lachy's ack was a formality. The second trip came at 18:18 and held all four slots and the lane idle until his ack at 09:28 the next morning: 15 hours of an overnight run lost to a decision with nothing left to decide. p26-1 and p26-3 make that miss rarer; they do not make a false trip impossible.

## Decision

**A window the canary cannot read (a Bookkeeping miss) never trips: it is logged with the checkout's state, read at that moment, and only a failing state check trips. A trip, while it stands, holds only what it threatens: the Integration lane, or the whole rollout when the checkout is bare. Every trip is acked by Lachy, and a RACE red twice is reverted on `main`.**

- **A Bookkeeping miss is classified at the check.** `record missing`, `record unreadable` and `record not armed` say only that a window was never armed or could not be read; they observed nothing. The check reads the state there and then: the Project root's `<default>` is an ancestor of origin's tip, read from GitHub as well as from the tracking ref (a forged tracking ref could match a bad local one), so no commit on it is missing from origin, while a peer's push since does not fail it; it has no tracked changes; and it is not bare. All three hold: the miss is logged in the `## Git-env log` with that state and holds nothing. Any one fails: it trips, as an observed change does.
- **An observed change always trips and is Lachy's.** The default branch moved, or `core.bare` flipped: a check read after the fact cannot show what the window saw, and a harmful change can be pushed or reverted before anyone looks. Only Lachy acks it; the Companion may gather its evidence and notify him (ADR 0048), never ack it.
- **The merge still checks its base.** A window with a logged Bookkeeping miss keeps its verify, since the state check showed the checkout unharmed. Integration goes on through merge-task, whose base check re-integrates when `main` moved.
- **A RACE's decision stays Lachy's; its hold narrows (ADR 0048).** A git-env halt at a RACE site keeps ADR 0030's rule that after the ack the task is an undecided RACE for Lachy (repair § 3e hands it to § 3c). A red RACE re-verify gets ADR 0050's Flake check first, so a load flake clears itself. Until a second red the RACE holds the Integration lane, never the whole rollout.
- **A RACE red twice is reverted.** The lead reverts that task's merge on `main` with a revert commit (never a force-push) and sets the task aside for Lachy, so `main` is green again, the lane frees and new starts branch from a green `main`. Lachy's decision is then about the task alone.
- **A trip holds what it threatens (ADR 0048).** A moved default branch, or a Bookkeeping miss whose state check failed short of a bare checkout, holds only the lane: each task's worktree is cut from `origin/<default>` after a fetch, never from the Project root's local ref, so starts, seeded revises and automatic retries continue, their windows armed and checked as usual, and a trip one finds joins the unacked set. A bare checkout (`core.bare` flipped, or `core.bare true at arm`) holds the whole rollout: linked worktrees share the root's config, so it reaches every task. Nothing new starts, running calls finish, and the restore runs once none is in flight.

## Considered options

- **A bookkeeping trip that acks itself (an Automatic ack)** on the same evidence: ruled in the re-grill, then replaced in the PR #202 simplify round (2026-10-22). It tripped, held the lane and then cleared itself, adding a term and a second ack writer for a case that observed nothing.

- **A red RACE holds the lane, new starts branch from the last green commit, or new starts wait too** (round 4 of the PR #202 review, 2026-10-22): rejected for the revert. Either `main` stays red overnight and every task rebases later, or the night idles again.
- **Self-ack only, the hold still freezing everything:** rejected. A real trip at night would still idle every slot until morning.
- **Lane-only hold, a false trip still tripping and waiting for Lachy:** rejected. It still loses the night's merges to a formality.
- **Any trip kind acks itself on stronger evidence** (the trip line's own recorded state, the moved ref merged by merge-task): rejected in the re-grill. Both false trips of `chorus-rollout-2026-10-18` were Bookkeeping misses, and an observed change is rare enough to be worth a look.

## How p29-2 built it

- **The canary's exit 9.** `git-env-canary.py` reads each unacked trip's scope (reconcile-rollout.py's `_git_env_scope`: `rollout` when the line reads `core.bare false→true`, `core.bare true at arm` or a failed state check's `core.bare true`, else `lane`). A whole-rollout hold exits 3 at every verb; a lane hold exits 9 at every site but a task window's, whose `arm` arms (printing `LANE HOLD:` lines) and whose `check` exits 0, its trip logged and joining the unacked set. Execute reads 9 as the lane held, never a halt.
- **The miss line.** A Bookkeeping miss runs the state check (not bare; no tracked changes; `<default>` an ancestor of origin's tip by `ls-remote` and by `origin/<default>` after a fetch through the configured refspec) and, passing, logs `git-env miss [[slug]] <kind>: <reason>; <each reading>; holds nothing; repo <R>`. `record missing` writes a closed `checked` tombstone carrying `miss`; `record not armed` leaves the tombstone untouched (its `ackedTrips` survive, ADR 0053); `record unreadable` becomes a tombstone its window's own check consumes, reading the state check again there and then (an earlier `check-all` may have logged the miss), so a change since trips the window. Failing, the trip line reads `<reason>, and the state check failed: <failure>`.
- **The budget and T == L.** The network reads share one budget under the canary lock: min(`THREAD_GIT_ENV_STATE_TIMEOUT`, 12 s; 0.4 × the lock timeout), each call in its own process group, killed on its timeout and never retried; the fetch is retried once only on a ref lock. The tracking ref after the fetch must equal the first `ls-remote` reading, or a second one, so a forged tracking ref or refspec cannot pass and a peer's push between the reads does.
- **`laneHold`.** `next` lists what holds the Integration lane: every unacked trip's slug, then each undecided RACE not reverted, or whose revert is pending (`revert: true`: started, not failed, `integrating:` standing), or reverted with `main not re-verified`. Starts, restarts, seeded revises and retries go on.
- **`halt: race`.** Once nothing starts, restarts or runs and the lane does not move, a lane `git-env` entry halts `git-env` and a `race` entry with `revert: false` halts `race`, ahead of `paused` and every older verdict.
- **`mainRed` and its at-once halt.** A RACE revert that did not land (`revert did not land:`) with no `RACE decided:` line holds every start (`main red: …`) and makes `halt` "race" at once, whatever runs, pauses or holds; execute's step 1.1 halts on it at every entry, ahead of every step-1.2 launch, until Lachy decides. It reads the rollout note alone, never the task note's status.
- **`revert` and its guard.** `lead-integrate.py revert` checks its target in the vault before any fetch (the note holds the lane, the task's own merge-task RACE line names `--merge`, `revert started:` stands, no `revert did not land:`), then that GitHub reads the PR merged as M, then opens, finds or reads as landed a revert PR on `thread-revert/<slug>-<M12>`. It never merges, never force-pushes and never writes the vault.
- **The four Race-log lines.** `revert started:`, `revert opened:`, `reverted on main:` and `revert did not land:` are the revert's only lines; merge-task's text, its `RACE:` line for the revert PR included, is never appended, and `revert`'s guard skips a RACE line for another PR.
- **`restores`, with its Inert reuse.** The revert's result frees the lane only when it restores M^1's tree: exactly, or but for paths prepare's own Inert check proves (ADR 0045, re-proved on that result, its Run-record line with base M^1). Any other landing since M keeps the lane held, `main not re-verified`, for Lachy: no verifier has run on that `main`.
- **Pending.** A revert stays pending until its landing tail's last write, the set-aside row that removes `integrating:`; step 1.4 resumes it on any entry.
- **The tail's order.** The `reverted on main:` line (only when absent), then `hold race end`, then the set-aside row, `tail.line` and `tail.reason` copied verbatim.
- **The exit-2 and exit-5 routes.** `revert`'s exit 2 with an `engine-snapshot:` line is re-run from the root it names, never a did-not-land; merge-task's exit 5 on a revert PR means it landed (`revert` routes `reverted`), never a did-not-land.
- **The merge-hold revert clause.** A revert PR's merge hold is released through `revert` (#R's pair), never this session's pair or the Integration log's last line, and a `--gated` decline is the revert's did-not-land, never a set-aside row.
- **The re-entry guards.** `resume`, `hand-back` and the automatic retry never re-enter a task whose `pr:` the revert reverted (reconcile-rollout.py `_reverted_pr`); a new `pr:` passes.

## Consequences

- `/thread:repair` § 3e remains the route for every trip; a logged Bookkeeping miss can be read, and questioned, in the `## Git-env log`.
