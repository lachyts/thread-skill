## Bounded native check contract (historical scope; both checks completed)

The following records the original bounded scope. Source-local checks have now
run without global candidate installation. It grants no repeat-probe allowance.

Run separately in each calling harness/account after candidate installation is
explicitly chosen. First capture runtime version, exact policy hash, role/model
availability, actual supported effort lists and active profile overrides. Keep
all evidence in a private project directory. If the interface cannot expose
reliable actual effort, record the check incomplete rather than infer it.

For each harness permit at most five native children, one each for easy work,
difficult work, independent built-in review, normal-model maximum and the
configured alternative at its maximum. If no alternative exists, use that final
slot to verify bounded same-model maximum and accurately record the unavailable
route. Use a scratch local repository and a tiny pre-existing diff with a known
acceptance check. Do not publish, merge or send external messages in this check.
No nested model process may substitute for a native child. A malformed output
may be corrected by its existing child once; missing capability is incomplete.

Collect actual model/effort from native tools separately from the requested
values. The independent review child must load the unmodified built-in review
engine, report the reviewed SHA, and yield native invocation evidence identifying
child, engine and review level. Claude command level remains xhigh even when
reasoning runs at maximum. No automatic `/code-review ultra` invocation.

Before any execution is initialised, exercise a deliberately conflicting profile
capability in the local resolver and confirm rejection. Native probes must then
show that the prepared profile correction takes effect at both starting and
maximum effort. Requested definitions alone are insufficient, as the old pilot
established. A probe failure consumes its slot; do not expand the check silently.

After those capability checks, separately prepare one tiny two-task rollout per
harness with explicit merge effects, exact user launch evidence and finite
allowances meeting the host's preflight minimum. Its agreement must cover the
chosen repository, base, verifier inputs, task outcomes and automatic merges.
Do not reuse prior pilot approval. Require independent built-in receipts, actual
effort observations, one genuine ownership recovery and preserved spending.
Record Stop delivery separately from heartbeat delivery on Claude.

The broader release still needs the outstanding domain promises: immediate
prerequisite release while unrelated work runs; pause holding a follow-on solely
because of pause; ambiguous/cold recovery; revision and revert revalidation;
partial ending and explicitly scoped relaunch; queued/changed-head protection.
Keep each claim tied to actual evidence, not a passing harness-labelled fixture.
